## إعادة الفحوص المحلية

نفذ الأوامر من جذر المستودع باستخدام Python 3.10 أو أحدث على POSIX:

<div dir="ltr">

```sh
python3 -B -m unittest discover -s tests -v
python3 tools/check_public.py
python3 tools/demo.py
python3 tools/package.py --output dist
```

</div>

تتحقق الاختبارات من انتقالات المراحل وتغطية المتطلبات وصلاحية أدلة المصدر والملفات وأعداد الاختبارات والمحاولات وأرقام الاستدعاء والمقاطعة وعقود المراجعة ومسارات المضيف والتثبيت. تشغّل GitHub Actions هذه الفحوص على Linux بإصدارات Python 3.10 و3.12 و3.14، وعلى macOS بإصدار 3.12. تعرض [صفحة الفحوص](https://github.com/M7MMAD-OMAR/sbar-checkpoint/actions/workflows/verify.yml) النتائج الحالية.

يعيد المثال المعزول إنتاج حساب فاشل عمدًا، ثم يصلحه وينفذ اختبارين. يجعل المراجعة غير مطلوبة في هذه التجربة الميكانيكية للمحرك ويصرح بأن `independent_review_performed: false`. أما [التجربة الكاملة](getting-started.ar.md#local-engine-walkthrough) فتحتاج مراجعًا مستقلًا بسياق جديد قبل الاعتماد.

تحتفظ الصفحات العربية والإنجليزية بأوامر التنفيذ وكتل JSON نفسها، مع ترجمة نصوص طلبات الوكيل. يمكن فحص روابط اللغة والعناوين المحلية دون استدعاء مزود نموذج.

## إعادة تجارب الوكلاء الفعلية

استخدم مشروع Python تجريبيًا، واحفظ الخطة والتشغيل والتقارير خارج المصدر، وسجل بصمات الملفات الأولية. جهّز وكيلك بطريقته المعتادة أولًا؛ المهارة لا تضبط بيانات الدخول ولا تختار مزودًا بالنيابة عنك.

| الواجهة | الاستدعاء | التجربة |
| --- | --- | --- |
| Codex | `$sbar-checkpoint` في سياق أصلي جديد | تخطيط بالعربية وتدقيق للقراءة فقط بالإنجليزية |
| Claude Code | `/sbar-checkpoint` في جلسة جديدة | تخطيط بالعربية وتدقيق للقراءة فقط بالإنجليزية |
| Hermes Agent | `--skills sbar-checkpoint` في جلسة one-shot جديدة | تخطيط بالإنجليزية وتدقيق للقراءة فقط بالعربية |

جُربت هذه المسارات باستخدام المهارة المثبتة ومحركها الفعلي. قارن فحص منفصل بايتات ملفات التجربة الواقعة في النطاق وانتقالات السجل وأعداد الاختبارات المسجلة. تثبت هذه الملاحظات السلوك المحلي الذي جرى، ولا تصادق على كل مزود أو إضافة أو بيئة سحابية. حفظ المصدر المحدد لا يعني ثبات شجرة المشروع كاملة: قد تولد إضافات المضيف فهارس أو ملفات مؤقتة.

في تجربة التخطيط اطلب مرحلتين مع اعتماد الثانية على الأولى، ووضع `plan`، وتشغيل doctor ثم `init` و`status` فقط. يجب ألا تُنفذ أوامر `start` أو `check` أو `prove` أو `accept`. يجب أن يحتوي السجل التهيئة فقط، وأن يبقى عدد الأدلة صفرًا.

في التدقيق استخدم هذه الدالة الخاطئة عمدًا:

<div dir="ltr">

```python
def visible_rows(rows, tenant):
    return [row for row in rows if row["active"]]
```

</div>

أضف اختبارين باستخدام unittest: يعيد الأول صفًا نشطًا للمؤسسة المطلوبة، ويشترط الثاني استبعاد صف نشط لمؤسسة أخرى. راجع أمر الفحص للتأكد من أنه للقراءة فقط، ثم اطلب تنفيذه عبر مرحلة `audit` باستخدام محلل `unittest` والحد `min_tests: 2`. النتيجة المفيدة تنفيذ اختبارين وفشل واحد متوقع يثبت تسرب صف المؤسسة الأخرى. يجب أن تبقى بوابة السلوك فاشلة والمراجعة المطلوبة معلقة. لا تصلح المصدر ولا تثبت أو تعتمد المرحلة في هذه التجربة.

استخدم ملف طلب مع مداخل التشغيل الأصلية دون واجهة تفاعلية، حتى لا يفسر shell نص الطلب كأوامر:

<div dir="ltr">

```sh
codex exec --sandbox workspace-write --ephemeral - < prompt.txt
claude -p --output-format json --no-session-persistence < prompt.txt
hermes chat --oneshot --skills sbar-checkpoint --query-file prompt.txt
```

</div>

يبدأ ملف Claude بـ`/sbar-checkpoint`، وملف Codex بـ`$sbar-checkpoint`. اختبار Codex CLI واختبار سياق سطح المكتب ملاحظتان منفصلتان. إذا لم يتوفر النموذج المضبوط أو بيانات الدخول لسطر الأوامر، سجل هذا الاستدعاء بأنه متعذر؛ نجاح المحرك لا يثبت نجاح استدعاء CLI. لا تتجاوز الصلاحيات أو تعدل إعدادات المزود أو تختلق مراجعة لإنهاء التجربة.

## فحص حزم التنزيل

يتضمن كل إصدار ZIP قابلًا للنقل وحزمة `.skill` مطابقة وبصمات SHA256. تحقق من التنزيل، وفك الحزمة في مجلد مؤقت تملكه، وثبتها في مجلد مضيف فارغ، ثم نفذ `scripts/workflow.py --version`. إصدار حزمة المهارة وإصدار المحرك منفصلان؛ يمكن لتحديث توثيق أن يحتفظ بإصدار المحرك نفسه.

اتبع [دليل التثبيت](getting-started.ar.md) و[فحوص المساهمة](../CONTRIBUTING.ar.md). أبق سجلات النماذج الخام وتفاصيل الحسابات والمسارات المحلية وملفات التشغيل خارج البلاغات والالتزامات العامة.
